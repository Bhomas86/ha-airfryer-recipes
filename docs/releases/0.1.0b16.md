# 0.1.0b16 – Share an entire device with ordinary HA users

[Deutsch](0.1.0b16.de.md) | [English](0.1.0b16.md)

Administrators can now grant ordinary users an **entire device**, including all its zones and available programs. Recipe library → Device permissions → Manage device access → choose user/device → Grant device access. No per-zone/program/menu grants. Ordinary users refresh their card; without a grant they see no device. Permissions persist across restart and are enforced in the backend, including before transmission and after revocation. Recipe management, permission changes and guided test tools stay admin-only.

Install b16 through HACS, restart HA and fully reload both sessions. First check with an ordinary account: no grant → no device; grant → both zones usable in test preview; revoke → no device after refresh. No new appliance send is needed for this acceptance. Existing card/history data remain; the resource updates automatically. Missing/damaged permission storage blocks ordinary access and preserves its file. The confirmed basic card tests are recorded separately from the pending new two-account native acceptance. [Behavior, scope and checklist](../reports/ISSUE_8_DEVICE_ACCESS.md).

Device sharing applies to Airfryer Recipes, not other integrations/vendor apps. Existing supervised confirmation, manual start, model/adapter/program/temperature checks and no-retry policy remain unchanged. Proof and wider temperatures remain deferred.

Passed locally: **203 Python and 93 frontend tests**, compilation, documentation and formatting. Native new permissions UI/HA, HACS/Hassfest and Python 3.14 not run; no GitHub Actions. After verifying b16 publication, older betas are retained as drafts with tags/code/assets preserved.
