# 0.1.0b19 – Refresh device artwork after saving

[Deutsch](0.1.0b19.de.md) | [English](0.1.0b19.md)

The owner confirmed that b18 saves the private device photo and zone positions, but the dashboard only shows the result after reloading the page. The open card cached its appearance and did not reread it after a save. b19 notifies cards on the same page after a successful save. Each affected card rereads the artwork through its existing authenticated, device-authorized API. Cards detached while the editor is open reread when reattached. Other tabs and devices still require their card's Refresh button.

The editor shows saving progress, disables repeat saves and places the success/error message above its buttons. A note explains the two independent saves: **Save appearance** commits the shared device artwork; the Home Assistant footer **Save** commits changed card options and can remain disabled when those options are unchanged. A failed save does not notify cards. The notification contains only the device identifier, never private image data. No public image route, new storage schema or appliance command is added.

Artwork reads discard outdated replies after a newer read, target change, account/role change or disconnect. Refresh waits for active card work; repeated notifications while busy are combined. Cooking drafts, zone selection, saved transmission history and confirmation tokens are preserved. Device grants and administrator-only image writes are unchanged. The requested alternatives to large zone overlays remain design proposals, pending the owner's choice.

Install v0.1.0b19 in HACS, restart HA and fully reopen the app once to load the updated module. Keep test mode enabled. As admin, edit the card → Customize Airfryer, move a zone slightly and press **Save appearance**. Check the visible success message, close the editor and verify the updated photo/zone positions without reloading the page. Repeat with a preset and with Restore defaults + Save appearance. Check another card for the same device on that dashboard updates; a different device must retain its own artwork. No cooking/transmission test is needed. Native HA/Companion acceptance of this correction remains pending.

Local validation: **212 Python tests and 115 frontend tests** (62 panel, 41 card, 4 actual module loading, 8 designer), compilation, paired documentation/link checks and git diff formatting. New coverage includes the designer-to-card event and authorized reread, delayed/failed saves, detached editors/cards, normal-user reads, notification coalescing and stale replies. These are offline DOM/transport mocks and Node module imports, not a native browser/HA run. HACS/Hassfest and Python 3.14 were not run. No GitHub Actions were triggered. Publish only b19 after verifying its tested tree/tag; retain older beta releases as drafts with tags, commits and assets preserved.
