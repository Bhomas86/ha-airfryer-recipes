# 0.1.0b18 – Private device artwork and relative zone editor

[Deutsch](0.1.0b18.de.md) | [English](0.1.0b18.md)

Admin card editor → Customize Airfryer opens an original neutral gallery (stacked, side by side, outline), device selector, private image upload and zone preview. Drag each zone or edit x/y/width/height percentages. Save explicitly; Restore defaults changes the draft and Save commits it, while Discard restores the last loaded/saved draft. Refresh the card after saving. All settings belong to the device and are shared across its authorized users. Layout changes send no appliance commands. Existing cards retain their original graphic unless customized.

Uploads accept actual PNG/JPEG/WebP bytes, at most 1 MB and 8 million pixels, single frame only. Pillow (already pinned by HA Core) decodes off the event loop and rebuilds PNG pixels without metadata, reducing size to at most 350 KB. SVG, GIF, corrupt/oversized images and overlapping/out-of-bounds/non-finite zone boxes are rejected. Private image data travels only through authenticated WebSocket messages: no public image URL, /local file, external image URL or third-party image fetch. Admin-only writes recheck the active administrator. Ordinary reads require a current whole-device grant and recheck it after loading. These permissions apply to Airfryer Recipes.

A separate version-1 HA Store, airfryer_recipes.appearance, keeps at most 32 device records. Failed writes retain the prior value; damaged/newer storage is preserved and customization fails closed, leaving recipe management and the neutral card fallback usable. Presets contain no manufacturer logo/photo or copied artwork. User images are never committed to GitHub or included in recipe exports. A Missing your model? issue link is included.

Install b18 via HACS, restart HA, reload the app and edit the card as admin. Open Customize Airfryer, select the device, choose a preset or image, position both zones and Save. Refresh the card, change its size and check the boxes stay aligned. Reopen the editor/restart HA to check persistence; test Reset + Save. Check a permitted ordinary user sees the graphic and cannot customize it; after revocation new reads must be denied. Keep test mode enabled; no appliance transmission is required. Owner confirmed the b17 editor works; new image-editor/native persistence acceptance remains pending.

Passed locally: 212 Python and 104 frontend tests (62 panel, 34 card, 4 module, 4 designer), compilation, links/language pairs and formatting. Coverage includes image normalization/metadata removal/type/size, rectangle validation, separate device storage/reset/restart/failure, permission routes, relative dragging and no implicit sends. Native HA/Companion image-editor checks, HACS/Hassfest and Python 3.14 were not run. No GitHub Actions; the workflow only lists the additional tests/Pillow dependency for a future authorized run. After verified publication only b18 remains published; older betas remain drafts with tags/code preserved.
