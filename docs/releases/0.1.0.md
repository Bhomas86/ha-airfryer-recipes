# 0.1.0 — First stable release

[Deutsch](0.1.0.de.md) | [English](0.1.0.md)

First stable release of the agreed Airfryer Recipes scope: local device-independent recipes, administrator management and validated import/export; two-zone dashboard and visual editor; private artwork and adjustable touch areas; backend whole-device grants; separate single-zone and SYNC/MATCH preparation; optional completion notices; allowlisted diagnostic preview and a readable authenticated download filename.

## Supported scope and upgrade

Preparation targets Cosori Turbo Tower Pro Smart **CAF-DC111S-AEU**. Single-zone sending/completion notices accept reviewed Airfryer Control **1.0.3-beta.3, 1.0.3 or 1.0.4-beta.1**. Combined SYNC/MATCH requires **1.0.3 or 1.0.4-beta.1**. No controller patch is required. Other devices may manage recipes; no unreviewed transmission is enabled. Home Assistant minimum in HACS: **2026.10.0**.

Install **v0.1.0** through HACS, restart Home Assistant and fully reopen the browser/Companion app. Existing recipes, favorites, grants, artwork, notification rules and history are preserved; no data-schema migration or automatic dashboard change. New cards default to server-enforced test mode. Administrators share an entire device with ordinary HA users in the recipe library; refresh the card afterward.

## Preparation and safety

Review exact settings and confirm once. SYNC uses both zone drafts; MATCH uses zone 1 for both zones. Both zones must freshly report idle/off. The own sender checks identity, permissions, recipes, expiry and report again after login at the device HTTP boundary. It does not invoke the controller's combined-action refresh path, replace controller functions, automatically reset zones, retry uncertain writes or request heating start. Start cooking physically at the appliance.

After an unknown result, inspect and cancel prepared programs physically, then explicitly request read-only re-arm. An accepted response means adapter acceptance, not independently measured physical settings. Local storage failure after acceptance is not a reason to resend.

Completion notices default off and require explicit administrator selection of zone and Companion service. Only an observed fresh cooking→finished transition triggers a notice; uncertain/interrupted sequences may intentionally produce none. Diagnostics exclude private IDs, names, network addresses, credentials, recipes and artwork. Download keeps the exact preview, requires active administrator/owner checks and uses **airfryer-recipes-diagnostics.json**.

## Acceptance and final validation

Owner confirms card/editor/artwork, whole-device permissions, persistence, the extended temperature/Proof reported-settings sequence, both SYNC/MATCH preparations, canceled confirmation without sending, no automatic heating start, diagnostic export, rule persistence and exactly one actual completion notice. This is owner-reported acceptance, not independent cloud device measurement or all-model/temperature-accuracy approval. The owner accepts the filename correction without another phone test.

Local baseline before final versioning: **291 Python 3.12 tests and 136 frontend tests passed**. Stable publication is gated on the final release PR passing **Python 3.12 and 3.14**, frontend tests, **HACS** and **Hassfest** for the final 0.1.0 metadata. Actual run results are recorded on the release PR and published release. CI uses mocks; no real appliance or user credentials.
