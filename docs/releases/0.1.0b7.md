# 0.1.0b7 – New test without HA restart

[Deutsch](0.1.0b7.de.md) | [English](0.1.0b7.md)

Experimental beta. New: **“Device checked – enable a new test”**. After stopping, cancel prepared programs physically, check both zones are idle/off and acknowledge this button. Backend reads fresh state, discards old tokens and enables a new attempt. Re-arming sends no control command, never retries automatically and requires no further HA restart. Pending calls and unsuitable states still block.

Adapter rejection now shows step, program, zone and any numeric error code. A possible need to reset between different programs remains unconfirmed; no automatic appliance reset was added.

Back up, redownload v0.1.0b7 in HACS, restart HA once for installation and fully reopen the app. Exactly Airfryer Control 1.0.2-beta.1. Then, when needed: cancel at the appliance → **Device checked – enable a new test** → show sequence → start once. Remain beside the appliance; do not press Start. [Details and repeat acceptance](../reports/ISSUE_7_MANUAL_RECOVERY.md).

Locally: 138 Python tests, 31 frontend tests, compilation and formatting passed. **No GitHub Actions started.** No HACS/Hassfest, Python 3.14 or real appliance tests for this change.
