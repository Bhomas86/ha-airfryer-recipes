# 0.1.0b14 – Card neben einer vorhandenen Rezeptansicht laden

[Deutsch](0.1.0b14.de.md) | [English](0.1.0b14.md)

Korrigiert einen reproduzierten Ladefehler, der den Eintrag von **Airfryer Recipes** im Kartenkatalog verhinderte, wenn bereits eine andere Version des Elements der Rezeptansicht geladen war. Das Panel vermeidet jetzt doppelte Elementregistrierungen; die Card importiert die aktuelle mitgelieferte Basisklasse direkt. Modul-URLs verwenden einheitlich b14. Rezepte, Fachhistorie und Sicherheitsprüfungen beim Senden bleiben unverändert.

In HACS **Airfryer Recipes auf v0.1.0b14 aktualisieren**, HA neu starten und die App vollständig neu laden/öffnen. Dashboard → Bearbeiten → Karte hinzufügen → **Airfryer Recipes**. Testmodus aktiviert lassen; die Sichtbarkeit kann ohne Senden von Geräteeinstellungen geprüft werden. Falls automatisches Laden weiter scheitert, die dokumentierte [Ressource als JavaScript-Modul und Prüfungen](../reports/ISSUE_8_CARD_LOADING.de.md) verwenden.

Lokal bestanden: **170 Python- und 84 Frontend-Tests**, einschließlich vier vollständiger ES-Modulladefälle mit tatsächlichem relativem Import und Abweisung doppelter Registry-Einträge. Kompilierung, Links/Sprachpaare und Formatprüfung bestanden. Native HA-/Companion- und Geräteabnahme, HACS/Hassfest und Python 3.14 wurden nicht ausgeführt. **Keine GitHub Actions gestartet.**
