# 0.1.0b14 – Load the card alongside an existing recipe panel

[Deutsch](0.1.0b14.de.md) | [English](0.1.0b14.md)

Fixes a reproduced module-loading failure that prevented **Airfryer Recipes** from registering in the card picker when another version of the recipe panel element was already loaded. The panel now avoids duplicate element registration; the card imports the current bundled base class directly. Module URLs use b14 consistently. Recipes, per-zone history and device-send safeguards are unchanged.

In HACS update **Airfryer Recipes to v0.1.0b14**, restart HA and fully reload/reopen the app. Dashboard → Edit → Add card → **Airfryer Recipes**. Keep test mode enabled; visibility can be checked without sending appliance settings. If automatic loading still fails, use the documented [JavaScript-module resource fallback and checks](../reports/ISSUE_8_CARD_LOADING.md).

Passed locally: **170 Python and 84 frontend tests**, including four full ES-module loading cases that retain the actual relative import and reject duplicate registry entries. Compilation, links/language pairs and formatting passed. Native HA/Companion and appliance acceptance, HACS/Hassfest and Python 3.14 were not run. **No GitHub Actions started.**
