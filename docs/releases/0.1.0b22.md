# 0.1.0b22 – Final review storage corrections

[Deutsch](0.1.0b22.de.md) | [English](0.1.0b22.md)

The owner confirms the card, completed 44-step reported-value sequence and Proof recipe workflow. The final review found two storage defects: deleted recipe favorites could accumulate beyond the loader's limit and prevent startup; HA Store could log a failed write without raising it, causing false save acknowledgements. b22 bounds favorite writes, prunes only the changing user's deleted references and verifies application Store files after atomic writes through an executor. Recipes, backups, favorites, device grants, history and artwork publish new state only after successful verification. Failed history saving after an accepted device transmission never causes a resend. No storage schema migration or new appliance command is added.

The reviewed controller remains exactly **Airfryer Control 1.0.3-beta.3**. Temperature/Proof limits, 44-step run, whole-device grants and default artwork B are unchanged. Existing data is retained; damaged/future stores are not automatically overwritten. [Complete review and remaining checks](../reports/FINAL_REVIEW.md).

Passed locally: **232 Python tests on both 3.12.14 and 3.14.8**, **125 frontend tests**, compilation, links/language pairs and formatting. Regressions include real temporary JSON files with simulated silent HA Store failures, favorite/delete/reload/user isolation, shutdown and accepted-send/history-failure handling. HA 2026.10.0's actual write handler was separately exercised with a fake failing write to confirm its swallowed exception. These are not native HA/appliance tests. No GitHub Actions, official HACS/Hassfest run or new physical transmission test.

Install b22, restart HA and reopen the app. With test mode enabled, save a harmless recipe edit and change a favorite. Then follow the [focused restart checklist](../LOCAL_TEST_CHECKLIST.md): after restarting, those changes, recipe/image/zone positions, A/B choice, grants and per-zone history must remain; no old send may resume. No appliance transmission or repeat of all 44 steps is needed for these fixes. The current native restart check and official HACS/Hassfest validation remain open before a release candidate. b22 is a corrective beta; after verification only b22 stays published, older betas remain drafts with tags/commits/assets preserved.
