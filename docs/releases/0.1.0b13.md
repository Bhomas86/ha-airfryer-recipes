# 0.1.0b13 – Neutral dashboard card with separate zone history

[Deutsch](0.1.0b13.de.md) | [English](0.1.0b13.md)

The approved 1A design is implemented as a bundled Home Assistant dashboard card: original neutral stacked-drawer graphic, tappable zones, recipe/manual values, program dropdown, temperature and duration. The visual editor supports title, optional device ID and test mode. **Last sent** shows the last adapter-accepted program/temperature/duration separately per device and zone, persisted across restart. Switching zones sends nothing; editing fields leaves that display unchanged. Existing recipes are preserved.

Back up, install `v0.1.0b13` in HACS, restart HA and fully reopen the app. Dashboard → Edit → Add card → **Airfryer Recipes**. The integration loads the module automatically. YAML fallback:

```yaml
type: custom:airfryer-recipes-card
title: Airfryer Küche
dry_run: true
```

**Test mode is the default and sends no device command.** Disabling it uses the existing administrator-only supervised beta sender with one exact-value confirmation. Start remains at the appliance. Last sent means adapter acceptance, not current appliance state or device confirmation; transmissions before this update are not reconstructed. Normal-user device permissions remain planned. No wider temperature limits or Proof support; existing adapter/model/state gates remain unchanged.

Passed locally: **170 Python + 80 frontend tests** (59 panel, 21 card), compilation and formatting. Documentation and local acceptance procedure: [dashboard report](../reports/ISSUE_8_DASHBOARD_CARD.md). Native HA/Companion layout, new appliance acceptance, HACS/Hassfest and Python 3.14 were not run. No GitHub Actions started.
