# 0.1.0b1 – First HACS test release

[Deutsch](0.1.0b1.de.md) | [English](0.1.0b1.md)

**Prerelease for manual testing. Not a stable release.**

This version makes the reviewed local recipe management available as a selectable HACS beta for the first time. It includes:

- setup and operation without Airfryer Control,
- persistent versioned recipe storage with create, edit, duplicate and confirmed deletion,
- search, categories, shared and personal favorites,
- validated JSON import and named JSON export,
- responsive German/English administrator UI,
- read-only Airfryer Control device discovery,
- a server-enforced device dry-run preview in the administrator panel.

The preview displays the reported device/zone, desired values, zone state and blocking reasons. It executes **no device command**. Live transmission, heater start, active-zone changes, SYNC/MATCH and a regular-user dashboard card are not included.

## Installation through HACS

Add the repository as a custom HACS integration repository if it is not already configured. Enable beta/prerelease versions on the repository page and use “Redownload” to select `v0.1.0b1`. Then restart Home Assistant, fully close the Companion App and reopen it.

Create a Home Assistant backup before installation. The complete local procedure is in the [test guide](../reports/ISSUE_7_DRY_RUN_UI.md). If anything changes on the air fryer during preview, stop testing immediately and preserve Home Assistant logs.

## Verification and known limits

The release revision passed 75 Python offline tests, 14 frontend tests, HACS, Hassfest, Python 3.12 and Python 3.14. Existing recipe management was previously accepted manually on HA OS/Core 2026.10.3; device discovery and dry-run preview have not yet been accepted locally.

Airfryer Control telemetry freshness, model-specific programs and value limits are not yet reliably verified. The safe send contract is being coordinated with the upstream project. This release therefore enables no live control. Report defects with version, reproducible steps and redacted logs; never publish credentials or device/account identifiers.
